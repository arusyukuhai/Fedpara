新規ルームの既定はTinyStories-1Mの公式configからランダム重みを安全に生成し、共有Genesisを作成します（学習済み重みは読み込みません）。Embedding・Position Embedding・LM Head・Attention・MLPにLoHaを適用し、共有Embedding/Headは二重更新しません。参加者が異なる初期重みを使用すると更新は互換になりません。既存ピアがオンラインなら署名付きモデルシャードを同期してから学習を開始します。同期中は「JOIN WAIT」になります。旧形式のルーム・SQLite履歴とは互換性がありません。継続FedSumはピア数で割らず実効更新差分を足します。ピア数が増えると発散しやすくなるため学習率に注意してください。LoHa因子・AdamWは設定した件数（既定20件）のローカル公開ごとに再初期化します。公開済み更新は学習済みベースに残ります。周期やプロトコルが異なるルーム・ジャーナルとは互換性がないので新規作成してください。

05 · 分散学習の有効性検証

OFFLINE / TINYSTORIES-1M / CONTINUAL LoHa

中央集権と分散で同じoptimizerを使用します。LoHa+AdamWまたはLoRA+LoRA-Muonを比較できます。同じ初期重み・トークン予算・入力データで測定。分散側はFedSum（更新差分の総和・ピア数で割らない）です。rank 16 / Attention+MLP のみ / LR 1e-4 / warmup+cosine / 勾配clip 1.0。TinyStories-1Mと同じ構造をランダム初期化し、本体を固定してLoHaだけで学習します（GPT-Neo、8層、隠れ幅64）。TinyStories は実データをネットワークから取得します。学習時のWebRTC通信は行いません。
