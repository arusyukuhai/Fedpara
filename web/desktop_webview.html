HUGGING FACE · REWARD MODEL

External frozen scorer, not the PPO value Critic. Standard scalar sequence-classification heads; custom remote Python code is never executed. Use a fixed 40-character commit SHA so peers cannot silently load different checkpoints. PPO JSONL needs only {"prompt":"..."} in this mode.

04 · VALUE CRITIC

Independent value estimator for PPO/GAE. Optionally share its trained value-head updates over signed P2P gossip; this is never a Reward Model.

Requires a checkpoint with an already-trained scalar value head. The backbone stays frozen; the value head trains locally or through signed P2P gossip. PPO state prefixes are retokenized for this Critic. The model may be substantially slower than the small local Critic.

P2P mode shares signed value-head parameter updates with PPO peers. Trajectory IS corrects local stale rollouts against the current Actor, without clipping; large importance weights can destabilize learning. v81 trajectory mode shares signed, SHA-256-committed behavior Actor checkpoints (bounded 64MiB, paged) alongside token IDs and verifiable rewards; each receiver recomputes old-Actor probabilities before applying any Critic step. Frozen base tensors must match byte-for-byte. This significantly increases network and disk use, and may reject very large adapters. Each receiver re-evaluates its current Actor and optimizes its own Critic. Parameter-delta broadcasts are disabled in this mode. This is conditionally unbiased in expectation, not a guaranteed global convergence protocol. New rooms only. Signed trajectories expose tokenized prompts and references to other room peers; use authorized data only.

These settings apply when launching a new worker; changing a room's pinned objective protocol requires a new room.
